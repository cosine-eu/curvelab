# An Experiment in AI-Assisted Coding

Coding agents have been with us for some time now, but since the
release of Claude Code by Anthropic, interest in their use has reached
a wider public.

At cosine we try to keep up with the development of technology, and
since the introduction of ChatGPT in November 2022 we have been
cautiously exploring the use of large language models in our
work. This experiment was born out of the need to understand to what
extent a coding agent can be deployed to write high-quality software.

## Selecting a Project

The project was selected to meet the following criteria:

- **No connection to existing contracts.** We have explicit and
    implicit confidentiality agreements with our customers and we want
    to honour them.

- **Domain expertise.** The project should be about something we know
    how to do. We want to be able to check what the coding agent is
    doing and correct it if it strays off course.

- **Substance.** The project should require real effort on our
    part. We want to learn complex usage patterns beyond asking the
    agent to solve small, isolated questions. We want the agent to
    reason about the structure of the code, examine what it has
    produced, and connect different parts into a coherent whole.

- **Usefulness.** The result should be something that could be used
    internally at cosine but also made available to a wider community.

## The Result: CurveLab

After some back and forth, the result was CurveLab. The name was
chosen by the agent. CurveLab is a graphical user interface to the
Python fitting package lmfit, with a few extensions. Its features are:

- Data in tabular form can be loaded from a wide variety of file
  formats and from the clipboard.

- New data can be generated by arbitrarily combining columns.

- XY plots can be generated, optionally with errors in X and Y. This
  is called a series.

- Series can be cleaned up by removing outliers using standard
  algorithms or by clicking individual data points away.

- Any of the one-dimensional models available in lmfit can be used and
  composed.

- Series can be fitted using any of the minimisers made available by
  lmfit. lmfit does not support fitting with errors in X; here we use
  ZZZ.

- Multiple series can be fitted to multiple models by creating
  multiple fitting sessions.

- Models can be compared using an F-test and by examining their ZZZ.

- Fitting can be limited to part of a series.

- The usual amenities offered by Matplotlib are available: line
  styles, different symbols, linear and logarithmic scales, and more.

- Test data sets can be generated from the model.

- A fitting session can be saved to a data file and reloaded at a later time.

## What We Concluded

**Coding agents are a fantastic piece of technology.** The ability to
  generate code by providing a description in natural language lowers
  the bar for inexperienced coders and offers new and interesting
  perspectives for the more experienced ones.

Coding agents are able to write syntactically correct code on the
first attempt. They are aware of prevailing coding conventions, know
how to use existing libraries, and are able to structure code in a
clear manner.

Coding agents are able to write good documentation, generate test
data, and write test harnesses — and they never write just one; they
always seem to write many.

Coding agents understand the build system in use and the repository
structure. They can adjust build files as required, add and remove
files from the repository, work with branches, identify conflicts, and
suggest solutions.

**All this comes with a few caveats, however.**

Coding agents, being backed by a large language model, must be used
with care, as they can hallucinate just like a chatbot. When the code
base the agent controls becomes complex, its assumptions and decisions
must be checked and questioned. The human developer must remain in
control to make sure the project stays on track. This is more than
just feature creep: when lacking sufficient information, an agent is
happy to fabricate evidence to justify what it is doing.

Coding agents do not know everything by default. Just like other LLMs,
they have a limited context, and progression through the code base
must be managed. We found that it is better to create many sub-agents
with different skills — this is, incidentally, what the makers of the
agents themselves suggest. A skill is a set of instructions that tells
the agent what it is supposed to concentrate on. In the end we created
an agent expert in data analysis, one expert in Python, a code
reviewer, a documentation writer, and a tester. Code written by one
agent would be reviewed by another and tested by a third.
